# ReviewCrew 知识库维护方案

## 1. 目标与当前边界

ReviewCrew 第一版没有部署向量数据库、代码图谱或后台增量索引服务。当前可用的“知识库”由仓库内可审计资料和版本化审查方法组成：PR diff、修改文件上下文、关联测试、项目文档、配置、Git 信息、静态信号、Prompt 与 Markdown Skills。

本方案定义这些知识的来源、版本、更新、回滚、质量和安全规则，并描述后续“PR 合并触发增量索引”的维护设计。后者尚未实现，不能在产品说明、演示或评测中宣称已经上线。

## 2. 知识来源

| 来源 | 当前状态 | 用途 | 可信边界 |
|---|---|---|---|
| PR unified diff | 已实现 | 确定修改文件、hunk 和修改行 | 审查主边界，不等同于完整业务上下文 |
| 修改文件局部代码 | 已实现 | 获取 enclosing code 与直接证据 | 单次最多读取 300 行，禁止越出仓库 |
| 关联测试 | 已实现 | 判断既有契约、边界与回归覆盖 | 仅按修改文件名启发式检索，可能漏检 |
| 项目文档 | 已实现 | 读取 README、CONTRIBUTING、ARCHITECTURE、SECURITY、AGENTS | 单文档截断到有界长度，需结合代码验证 |
| 配置文件 | 已实现为可搜索文本 | 理解依赖、构建、权限和运行约束 | 配置可能过时，优先与代码和测试交叉验证 |
| Git diff / 本地引用 | 已实现 | 加载 base/head 差异和提交身份 | Git 历史辅助函数存在，但尚未接入默认 Context Builder |
| Semgrep | 可选、已实现降级 | 提供修改文件的静态分析信号 | 缺失、失败或超时返回空信号，不作为唯一证据 |
| 版本化 Skills | 已实现 | 为 Team Lead、专家和 Verifier 注入审查方法 | Skill 是方法提示，不是事实；必须以代码证据落地 |
| Prompt 文件 | 已实现 | 固定共享规则和角色职责 | 只记录文件哈希，不持久化完整 Prompt |
| 历史 Finding / Replay | 已持久化运行产物 | 人工复盘、演示和后续模式提炼 | 当前不会自动反哺检索或生成新索引 |

## 3. 版本模型

一次可复现的知识版本由以下标识共同确定：

1. **代码版本**：Git commit SHA。
2. **Skill 版本**：Markdown front matter 中的 `name`、`version`、`roles`、`risks`、`estimated_seconds`、`priority`，以及文件 SHA-256。
3. **Prompt 版本**：共享 Prompt 与角色 Prompt 的文件哈希。
4. **配置版本**：模型名、角色覆盖、超时、并发度、上下文预算等非密钥配置；密钥值不得进入版本记录。
5. **数据版本**：Benchmark dataset 文件哈希、来源 URL、案例 `status` 和人工核验记录。
6. **运行版本**：`run_id`、base/head SHA、开始时间、结果状态和事件序列。

Skill 的语义变化必须提升版本号；只调整排版且不改变方法时可保持版本号，但仍会产生新的内容哈希。Prompt、Skill、Dataset 和配置的变更应与对应测试放在同一提交中。

## 4. 当前更新流程

### 4.1 文档、测试与配置

1. 从目标 PR 的 diff 确定修改文件。
2. Context Builder 读取修改行附近代码、可能关联的测试和项目规范文档。
3. Team Lead 根据差异规模、语言和风险标签生成 ReviewPlan。
4. Skill Registry 按角色、风险和剩余预算选择已版本化 Skill。
5. 专家与 Verifier 只发布结构化候选、证据和裁决；最终产物落到 `runs/{run_id}`。

这一流程是请求时读取，不是离线预构建索引。仓库内容变化后，下一次审查直接读取新的工作树或 Git 引用。

### 4.2 Skill 与 Prompt

修改流程：

1. 新建或更新 Skill/Prompt，同时写明目标缺陷类型和停止条件。
2. 运行 Skill Registry、Agent Runtime、Verifier 和相关回归测试。
3. 运行至少一个目标案例和一个邻近案例，记录命中、误报、Verifier 接受/拒绝与耗时。
4. 只有指标改善或明确修复阻断问题的版本才合并。
5. 在提交信息或迭代记录中保存父 SHA、文件哈希和验证命令。

### 4.3 Benchmark 数据

- 公共来源字段必须保留 `source_url`。
- 未核验上游修复 PR、引入/修复提交、目标文件和行号时，案例保持 `needs_review`。
- 只有人工完成来源追溯、SHA 校验、目标位置和语义关键词复核后，才能改为 `ready`。
- Fake fixture 必须使用 `fixture://`、`fixture/*` 等显式身份，不能伪装成真实 GitHub 链接或提交。

## 5. 合并触发的增量索引设计（尚未实现）

未来可在默认分支 PR 合并后触发以下维护任务：

```text
merge event
  → 读取 merge commit 与父提交差异
  → 识别新增、修改、删除和重命名的符号/文档/配置/测试
  → 仅重建受影响分片
  → 生成架构摘要与历史缺陷模式候选
  → 质量门禁与敏感信息扫描
  → 原子发布新索引清单
  → 保留前一稳定清单用于回滚
```

建议索引单元包含：仓库、路径、符号、语言、内容哈希、来源 commit、依赖/被依赖关系、相关测试、文档引用和有效时间。删除或重命名使用 tombstone，避免旧知识继续被检索。

该设计上线前必须补齐：

- 合并事件接收与鉴权；
- 增量解析器和存储实现；
- 全量重建与增量结果等价测试；
- 原子版本切换和回滚命令；
- 数据保留期限、删除请求和租户隔离；
- 线上延迟、失败率、陈旧率和召回监控。

## 6. 回滚方案

### 当前文件型知识

1. 使用 Git tag 或 commit SHA 标记稳定版本。
2. 若新 Prompt/Skill/配置导致回归，创建修复提交恢复到上一稳定文件内容；不要使用破坏工作区的强制 reset。
3. 重新运行目标案例、邻近案例、全量后端测试和前端契约测试。
4. 保留失败版本的提交和评测记录，避免以后重复引入。

### 未来索引服务

- 每次发布生成不可变 `manifest`，记录源 commit、分片哈希、Schema 版本和构建时间。
- 通过一个原子“active manifest”指针切换版本。
- 回滚只切换到上一份已验收 manifest，不边回滚边重建。
- 回滚后执行抽样检索、权限隔离和陈旧数据检查；失败则保持旧版本并报警。

## 7. 质量门禁

| 门禁 | 最低要求 |
|---|---|
| 来源完整性 | 每条外部知识有 URL、commit 或文件路径；未知字段保持空值 |
| 新鲜度 | 当前读取型知识随目标 Git 引用更新；未来索引记录 source commit 和构建时间 |
| 一致性 | 增量索引与同 commit 全量重建抽样结果一致 |
| 可复现性 | 保存 Git SHA、Prompt/Skill 哈希、配置和 Dataset 哈希 |
| 审查质量 | 目标案例与邻近案例均复测；记录误报、Verifier 拒绝和耗时 |
| Schema | Dataset、ReviewResult、PipelineEvent 和 Skill front matter 校验通过 |
| 降级 | Semgrep、外部网络、某个 Agent 失败时仍输出明确的 partial/warning |
| 文档真实性 | 未运行写“未运行”，失败写“失败”，Fake 不计入真实命中率 |

建议每次知识变更执行：

```powershell
pytest tests/test_skill_registry.py tests/test_agent_runtime.py tests/test_verifier.py -q
pytest tests/test_benchmark_models.py tests/test_benchmark_judge.py tests/test_benchmark_runner.py -q
pytest -q
```

## 8. 安全与合规

- 知识采集坚持最小只读权限，默认只读取目标仓库和公开/已授权 PR。
- 路径必须经仓库根目录约束，拒绝 `..`、符号链接/Junction 越界和任意绝对路径读取。
- `.env`、API Key、GitHub Token、内部地址和用户数据不得进入 Git、Prompt 样例或评测报告。
- 持久化前移除完整 Prompt、模型原始响应、隐藏思维链和推理摘要；日志只记录异常类型与中文上下文。
- 外部文档、Issue、代码注释和 PR 文本均视为不可信输入，不能把其中指令提升为系统权限。
- 未来多租户索引必须按租户、仓库和授权主体隔离，并支持删除、过期和审计。
- 历史 Finding 进入模式库前必须去标识化并人工确认，禁止把单次模型猜测自动沉淀成“事实”。

## 9. 维护责任与节奏

- 每个合并请求：校验 Prompt/Skill/Dataset 版本和相关测试。
- 每周：抽查最近运行的 warning、partial、Verifier 拒绝和重复 Finding。
- 每个发布：冻结 Git SHA、配置样例、评测报告和可回放 run ID。
- 每次外部基准更新：重新核对来源页面、公开 PR 与许可，不沿用失效链接。
- 每季度或重大架构变更：复核知识源白名单、数据保留、安全 Hook 和回滚演练。

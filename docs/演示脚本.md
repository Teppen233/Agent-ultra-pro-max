# ReviewCrew 三分钟演示脚本

## 准备

1. 启动 FastAPI 与 Vite，确认 `/api/health` 返回 `ok`。
2. 浏览器打开 `/review`，使用 1280×720 或 1920×1080。
3. 无真实 run 时使用内置“演示 Replay”；它不调用模型，不依赖网络。
4. Benchmark 若显示“演示数据”，旁白必须明确这是界面示例，不宣称正式成绩。
5. 正式录制前关闭通知并检查画面中没有 API key、私有仓库路径或敏感 diff。

## 分镜

| 时间 | 操作与画面 | 旁白重点 |
|---|---|---|
| 0:00-0:15 | `/review` 空任务图，点击“演示 Replay” | ReviewCrew 不预设 Pipeline，Coordinator 会根据本次 diff 动态建立任务图。 |
| 0:15-0:35 | 点击“演示 Replay” | 审查过程被编码成统一事件流，实时模式与 Replay 使用同一前端状态机。 |
| 0:35-1:10 | Coordinator 派发三个任务，任务节点并发运行 | Defect 与 Intent 不是固定单例，Coordinator 会按风险和上下文启动多个任务实例。 |
| 1:10-1:35 | ThoughtStream 出现 `read_file` 与 `get_callers` | Agent 不只生成结论，还会按需读取代码、追踪调用者并收集证据。 |
| 1:35-1:55 | 两张 Finding 卡出现，一张被划掉 | Verifier 主动找反证、重评分；低于 0.6 的结论被过滤，最终最多保留 8 条。 |
| 1:55-2:25 | 点击右侧 Diff 图标，展示红色命中行与完整 Finding | Finding 精确锚定文件和行号，并可复制成 GitHub Review Comment。 |
| 2:25-2:45 | 切到 `/benchmark`，展示热力图和明细表 | 这里消费真实 harness 结果；当前若标注演示数据，就只说明评测界面，不播报命中率达标。 |
| 2:45-3:00 | 回到驾驶舱或显示架构图 | 离线 Profile、静态信号、多 Agent 推理和对抗验证共同提高可操作性。 |

## 正式评测版替换项

获得授权 50-PR 数据后，将内置 demo 替换为最佳真实 `run_id`：

```text
http://127.0.0.1:5173/review/<run_id>?mode=replay&speed=1.5
```

此时旁白中的指标必须逐字来自 `benchmark/results/<final>/summary.md`，并确认 Benchmark 页不再显示“演示数据”。

## 录制检查

- 总时长不超过 3 分钟。
- 画面至少 1080p、30fps，文字清晰。
- 拓扑、事件流、Verifier 淘汰、Diff 标记、Benchmark 五个核心画面都出现。
- 页面无 toast 错误、控制台错误、遮挡或水平溢出。
- 不展示密钥或受限源码。
- `demo.mp4` 需人工用 OBS/QuickTime 录制并检查后再纳入交付；仓库当前不伪造视频文件。

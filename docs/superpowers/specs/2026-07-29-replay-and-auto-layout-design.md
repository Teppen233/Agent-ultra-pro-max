# ReviewCrew 可控回放与动态图布局设计

## 目标

历史任务必须可以在不刷新页面的情况下查看和回放。用户可以播放、暂停、重新开始、拖动进度、单步前进或后退，并选择 `0.5x`、`1x`、`2x`、`4x`。任务图不再依赖固定画布尺寸和硬编码泳道坐标，而是随实际调度拓扑自动布局，并在调度推进时聚焦当前变化。

## 回放模型

历史任务详情接口继续返回完整事件数组。前端将完整数组保存在 `replayEvents`，并用 `replayIndex` 表示已经应用到界面的最后一个事件位置。

- 点击已完成的最近任务时，先显示最终状态，同时展示回放控制条。
- 点击播放或重新播放后，从当前进度继续；位于末尾时从 0 开始。
- 暂停保留当前状态。
- 上一步、下一步和拖动进度都会暂停，并通过从空状态重新归约 `0..replayIndex` 的事件恢复精确界面。
- `1x` 使用压缩后的偏慢基础节奏。相邻事件延迟受上下限约束，避免真实模型等待造成几十秒静止，也避免密集事件一闪而过；其他速度按倍率缩放。
- 回放完成后停在最终状态，不自动清空。
- Demo 与真实历史任务共用同一套回放控制器，不保留两套定时逻辑。

进度条显示当前事件序号、事件总数和百分比。没有可回放事件时禁用所有回放按钮。

## 实时更新

打开仍在运行且尚无 `report` 事件的任务时，页面连接实时 SSE。SSE 从已有事件开始发送，因此前端先清空可视状态，再以同一个 reducer 消费事件，避免历史快照与流事件重复。收到新事件后页面立即更新，不需要刷新。

任务完成并收到 `report` 后，关闭实时流，将已接收事件保存为可回放事件，控制条自动切换到历史回放模式。

## 控制条

新增独立 `ReplayControls` 组件，位于任务图标题下方，包含：

- 重新开始按钮。
- 上一步按钮。
- 播放/暂停按钮。
- 下一步按钮。
- 事件进度滑块。
- 当前事件与总事件计数。
- `0.5x / 1x / 2x / 4x` 分段速度选择。

所有按钮使用 Lucide 图标、tooltip、hover 和 active 状态。播放中拖动或单步会先暂停。移动端控制条允许分行，但按钮和文本不得溢出。

## 自动布局与聚焦

使用拓扑分层布局替代 `WorkflowKind` 固定坐标。节点层级由事件边关系计算：输入和 Coordinator 靠前，依赖、派发、候选、验证与报告沿主方向展开；同层节点按稳定 ID 排序，避免已有节点在每次事件后无意义跳动。

画布不再写死 36rem 高度。布局结果计算内容边界，容器高度在合理最小值之上随拓扑增长，宽内容通过 Vue Flow 的平移与缩放查看。

聚焦规则：

- 新节点进入或节点首次变为 `running` 时，平滑聚焦该节点，并保留足够上下文。
- 一次事件批量恢复或拖动进度时，对当前最后变化节点聚焦一次，不逐节点抖动。
- 回放结束和首次加载最终状态时执行一次全图适配。
- 用户手动平移后，仅在新的调度事件到来时恢复自动聚焦。

边继续区分 dispatch、handoff、evidence、challenge 等关系。自动布局通过增加层间距和同层间距降低交叉，不承诺任意有向图完全无交叉，但不得出现节点互相覆盖。

## 状态与错误处理

Pinia 负责回放源事件、当前位置、播放状态、速度、计时器和实时流。路由切换、加载其他任务或组件卸载时必须取消计时器并关闭旧 EventSource。

历史详情加载失败使用现有 toast。实时连接在任务已经有报告时关闭不报错；未完成时异常中断才显示错误。拖动进度和单步操作不请求后端。

## 测试与验收

- Store 测试覆盖播放状态、前进、后退、seek、末尾重播、速度切换和 reducer 重建。
- 组件测试覆盖按钮禁用状态、速度选择和事件发射。
- 后端回放与运行详情契约保持现有测试通过。
- TypeScript strict、ESLint、Vitest 和生产构建全部通过。
- 浏览器验证已完成历史任务无需刷新即可更新、进度拖动正确、四档速度有效。
- 桌面与 390px 移动端验证无横向溢出、节点不重叠，新增运行节点会自动聚焦。

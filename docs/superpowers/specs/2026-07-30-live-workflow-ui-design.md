# ReviewCrew Windows 审查工作台 UI 重构设计

## 目标

将当前由多个固定面板拼接而成的界面重构为 Windows 桌面端审查工作台。任务拓扑是审查页的主要工作区，调度、实时事件与审查结论作为辅助信息按需展开。同步统一 Diff 与 Benchmark 的页面框架、视觉层级和交互反馈。

修复任务图在现场运行时依赖最终任务结果预留空间的问题，使布局只由当前已经出现的节点和连接决定。新增节点后允许已有节点平滑重排，保持清晰的执行拓扑。后端、接口、事件格式与任务执行逻辑保持不变。

## 当前问题

`AgentFlow` 当前使用完整 `replayEvents` 派生的最终拓扑计算坐标。历史回放看起来相对稳定，但现场运行没有完整拓扑时，新节点只能在碰撞后持续向右平移，无法重新平衡分支。现有递归算法也把一般有向图当作严格树处理，多父节点、验证回流和跨层关系会产生错误的子树宽度。

边没有声明固定连接锚点，Vue Flow 会根据节点相对位置选择路径。节点增量出现或重排时，路径可能从侧面进入、穿过相邻节点或在同一区域叠加。节点 CSS 实际高度还可能超过布局使用的固定高度，进一步放大连线偏差。

页面信息架构也没有清晰主次。运行表单占用完整横向区域，左右栏使用固定比例持续挤压任务图；无数据时仍保留大面积空面板；实时事件固定放在图下方，增加页面高度却不能和图并行查看。新增节点后自动聚焦会把单个节点放大到接近整个画布，用户失去拓扑上下文。

全局导航、审查页、Diff 与 Benchmark 各自定义页面标题和面板规则，间距、字号、边界及状态表达缺少统一工作台语法。当前视觉大量依赖细小文字、单像素分割线和近似色，扫描效率偏低。

## 工作台信息架构

全局使用固定高度的 Windows 桌面应用栏，保留产品标识、审查与 Benchmark 导航、API 状态。应用栏与页面内容使用统一高度、边界、选中态和焦点反馈。

审查页分为四个区域：

- 顶部运行栏：单行容纳 PR 或 Diff 输入、仓库路径、开始操作、演示入口和当前 Run 状态。没有运行时突出输入；运行后弱化表单并突出状态。
- 左侧调度栏：展示并发指标、当前任务和关键调度记录，支持折叠，不重复展示任务图已经清楚表达的低价值信息。
- 中央主工作区：任务拓扑占据剩余主要面积，回放控制与图工具作为紧凑工具栏，不再拆成多层标题区。
- 右侧结论栏：展示 Finding 列表和统计，支持折叠。无 Finding 时使用紧凑状态而不是整栏居中空白。

实时 Agent 事件改为中央工作区底部可展开面板。面板关闭时显示最新事件摘要和未读计数，展开后在有限高度内滚动，不推动整页无限增长。左右辅助栏的折叠状态保留在组件本地状态，不引入新的全局状态方案。

## 实时布局

使用项目已经安装的 `@dagrejs/dagre`，每次当前可见节点 ID 或当前可见边发生变化时同步计算布局。布局输入仅使用 `workflowNodes` 和 `workflowEdges`，不使用最终回放数据，因此实时运行与历史回放执行完全相同的规则。

- 主方向为从上到下。
- Dagre 节点尺寸与组件渲染尺寸使用同一组常量。
- 层间距为连线转折和箭头预留空间，同层间距防止节点与标签拥挤。
- 同一批节点使用稳定 ID 作为次序依据，减少无意义换位。
- 节点更新时直接替换目标坐标，由 Vue Flow 节点 transform 过渡完成平滑重排。
- 首次出现图时适配全图；后续新增节点保持当前缩放并温和调整视口，使新增节点进入可视区域但不放大到单节点。状态更新不触发视口移动。
- 空图、单节点、孤立节点和包含回路的图必须有确定位置且不得重叠。

删除 `layoutWorkflowNodes`、`layoutWorkflowEdges` 和 `layoutKey` 在任务图组件中的布局职责。为避免扩大状态层改动，本次可以暂时保留 Store getter，但组件不再消费它们。

## 连线规则

所有主流程节点使用顶部目标锚点和底部源锚点，使主流程边保持统一方向。普通派发、依赖、候选和结果关系使用正交 `smoothstep` 路线。

关系边分为三个视觉级别：

- 主流程关系使用低对比度实线，运行中的相邻边提高亮度并动画显示。
- `handoff` 与 `challenge` 使用各自语义色和不同虚线节奏，保留可辨识度。
- `evidence` 作为辅助关系降低不透明度和线宽，避免压过主流程。

多条边共享端点时允许在锚点附近汇聚，但路径不得穿过节点内容。箭头颜色跟随边颜色。聚焦节点时突出其上下游边，其余边适度降噪。

## 节点与画布 UI

任务节点采用稳定宽高，正文严格限制行数，避免运行中标签或详情改变节点几何尺寸。节点由类型、标题、摘要和状态四个信息层级组成，状态用文字与色彩共同表达。运行、完成、失败、选中和聚焦状态继续使用现有设计 token，不引入裸写色值。

任务图标题区、回放控制和图工具合并为一条工作区工具栏，修复重复的“当前聚焦”文本。缩放、适配和聚焦按钮保持图标按钮与 tooltip，并补齐 hover、active 和 focus-visible 反馈。空状态保留明确的启动引导。

节点和画布继续使用现有语义色，但提高文字尺寸、行高和前后景对比度。节点状态使用图标、文字与边界共同表达，避免只靠颜色。画布背景、聚焦轮廓和边的层级应明显但克制。

## Diff 与 Benchmark

Diff 页面使用与审查页一致的工作台标题栏。代码区域保持横向滚动和稳定行号列，Finding 详情为固定宽度侧栏；点击标记行时更新详情并突出关联范围。复制操作使用现有 toast，禁用与成功状态必须清楚。

Benchmark 页面使用统一标题栏和内容网格。指标区强调数值与目标差异，热力图与明细表使用一致的面板标题、加载状态和数据来源标签。演示数据必须被清楚标识，接口失败继续使用 toast，页面仍可展示演示数据。

三个页面共享全局 token、页面标题、工具栏、空状态、滚动区域和交互反馈规则。仅在真实重复出现时提取小型布局组件，不引入新的 UI 框架。

## 数据与边界

后端事件、SSE、Pinia reducer 和接口契约保持不变。前端图组件从当前 Store 可视状态接收数据，处理流程为：事件进入 Store、当前节点/边更新、Dagre 生成目标坐标、Vue Flow 平滑移动节点并重绘边。

布局失败时回退为按稳定顺序排列的网格坐标，不能让全部节点堆叠在原点。未知端点的边继续过滤。重复边和回路交给 Dagre 排序，渲染层不抛出异常。

## 验证

- 为布局逻辑添加单元测试，覆盖空图、单节点、并行分支、多父节点、孤立节点和增量节点。
- 验证节点坐标不重叠，主要层级沿垂直方向递增，输入顺序不影响稳定结果。
- 运行 `npm run typecheck`、`npm run lint`、`npm run test` 和 `npm run build`。
- 在浏览器播放 Demo，并检查现场增量场景中节点平滑重排、边不穿过节点、视口不持续跳动。
- 在 Windows 桌面常用的 1366×768、1536×864 和 1920×1080 视口检查审查、Diff 与 Benchmark。
- 确保 Windows 浏览器默认缩放下控件、节点文字和辅助栏没有重叠，主要操作无需横向滚动。

## 不在范围内

本次不修改后端、任务调度策略、事件格式、回放业务逻辑，也不引入新的图布局依赖、UI 框架或状态管理方案。移动端、平板、macOS 与 Linux 的专项适配和验收不在范围内；不主动破坏已有 CSS 的自然降级，但不为这些端增加专门布局。

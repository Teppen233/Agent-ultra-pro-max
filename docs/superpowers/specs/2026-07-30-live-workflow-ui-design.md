# ReviewCrew 实时任务图与驾驶舱 UI 优化设计

## 目标

修复任务图在现场运行时依赖最终任务结果预留空间的问题，使布局只由当前已经出现的节点和连接决定。新增节点后允许已有节点平滑重排，保持清晰的从上到下层级。同步优化审查驾驶舱的信息密度、控件层级和响应式表现，但不修改后端、接口与事件格式。

## 当前问题

`AgentFlow` 当前使用完整 `replayEvents` 派生的最终拓扑计算坐标。历史回放看起来相对稳定，但现场运行没有完整拓扑时，新节点只能在碰撞后持续向右平移，无法重新平衡分支。现有递归算法也把一般有向图当作严格树处理，多父节点、验证回流和跨层关系会产生错误的子树宽度。

边没有声明固定连接锚点，Vue Flow 会根据节点相对位置选择路径。节点增量出现或重排时，路径可能从侧面进入、穿过相邻节点或在同一区域叠加。节点 CSS 实际高度还可能超过布局使用的固定高度，进一步放大连线偏差。

## 实时布局

使用项目已经安装的 `@dagrejs/dagre`，每次当前可见节点 ID 或当前可见边发生变化时同步计算布局。布局输入仅使用 `workflowNodes` 和 `workflowEdges`，不使用最终回放数据，因此实时运行与历史回放执行完全相同的规则。

- 主方向为从上到下。
- Dagre 节点尺寸与组件渲染尺寸使用同一组常量。
- 层间距为连线转折和箭头预留空间，同层间距防止节点与标签拥挤。
- 同一批节点使用稳定 ID 作为次序依据，减少无意义换位。
- 节点更新时直接替换目标坐标，由 Vue Flow 节点 transform 过渡完成平滑重排。
- 首次出现图时适配全图；后续只在新增节点时聚焦新增节点的上下文，避免状态更新触发视口抖动。
- 空图、单节点、孤立节点和包含回路的图必须有确定位置且不得重叠。

删除 `layoutWorkflowNodes`、`layoutWorkflowEdges` 和 `layoutKey` 在任务图组件中的布局职责。为避免扩大状态层改动，本次可以暂时保留 Store getter，但组件不再消费它们。

## 连线规则

所有主流程节点使用顶部目标锚点和底部源锚点，使主流程边保持统一方向。普通派发、依赖、候选和结果关系使用正交 `smoothstep` 路线。

关系边分为三个视觉级别：

- 主流程关系使用低对比度实线，运行中的相邻边提高亮度并动画显示。
- `handoff` 与 `challenge` 使用各自语义色和不同虚线节奏，保留可辨识度。
- `evidence` 作为辅助关系降低不透明度和线宽，避免压过主流程。

多条边共享端点时允许在锚点附近汇聚，但路径不得穿过节点内容。箭头颜色跟随边颜色。聚焦节点时突出其上下游边，其余边适度降噪。

## 节点与画布 UI

任务节点采用稳定宽高，正文严格限制行数，避免运行中标签或详情改变节点几何尺寸。节点由类型、标题、摘要和状态四个信息层级组成，状态用文字与色彩共同表达。运行、完成、失败、选中和聚焦状态继续使用现有设计 token，不引入裸写色值。

任务图标题区合并重复信息，修复重复的“当前聚焦”文本。缩放、适配和聚焦按钮保持图标按钮与 tooltip，并补齐 hover、active 和 focus-visible 反馈。空状态保留明确的启动引导。

驾驶舱保持左侧调度、中间任务图、右侧结论的工作流，但调整三栏最小宽度、边界和滚动行为：宽屏优先给任务图，较窄桌面下压缩两侧栏；移动端改为单列自然顺序，不产生整页横向滚动。任务图使用受约束的响应式高度，避免固定大高度在小屏上挤压其他内容。

## 数据与边界

后端事件、SSE、Pinia reducer 和接口契约保持不变。前端图组件从当前 Store 可视状态接收数据，处理流程为：事件进入 Store、当前节点/边更新、Dagre 生成目标坐标、Vue Flow 平滑移动节点并重绘边。

布局失败时回退为按稳定顺序排列的网格坐标，不能让全部节点堆叠在原点。未知端点的边继续过滤。重复边和回路交给 Dagre 排序，渲染层不抛出异常。

## 验证

- 为布局逻辑添加单元测试，覆盖空图、单节点、并行分支、多父节点、孤立节点和增量节点。
- 验证节点坐标不重叠，主要层级沿垂直方向递增，输入顺序不影响稳定结果。
- 运行 `npm run typecheck`、`npm run lint`、`npm run test` 和 `npm run build`。
- 在浏览器播放 Demo，并检查现场增量场景中节点平滑重排、边不穿过节点、视口不持续跳动。
- 检查桌面与移动视口，确保控件、节点文字和三栏内容没有重叠或横向溢出。

## 不在范围内

本次不修改后端、任务调度策略、事件格式、回放行为和其他页面业务逻辑，也不引入新的图布局依赖或状态管理方案。

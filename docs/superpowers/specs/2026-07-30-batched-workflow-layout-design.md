# ReviewCrew 批量派发布局、关系边与调度栏优化设计

## 目标

消除 Coordinator 连续派发多个子 Agent 时任务图反复横移、缩放和重新居中的跳变，修复默认边路由造成的重线、跨层回绕和端点拥挤，并降低左侧调度栏的信息密度。新任务仍需立即可见，但已有节点在派发批次完成前保持原位。后端事件、调度逻辑和回放数据不变。

## 当前原因

`AgentFlow` 直接以当前节点和边计算 Dagre 布局。每个 `workflow_node` 或 `workflow_edge` 事件都会改变计算结果，新兄弟节点加入后 Dagre 会重新居中整个同层分支。节点的 transform 动画尚未结束时下一次布局又开始，导致已有节点连续左右移动。

视口适配虽然已有防抖，但节点位置本身仍在每个事件上更新，因此无法解决派发期间的视觉跳动。

当前所有关系使用 Vue Flow 默认 `smoothstep`。多个 `dispatch` 共享一段主干；同层 `handoff` 横跨整层；Verifier 返回 Finding 的 `result` 反向边会从树中心长距离向上回绕。这些路径与主流程边互相覆盖，箭头又集中在节点上下中心，无法快速判断连接来源。

左侧栏同时展开并发指标、四类状态计数、全部任务、六条调度记录、变更文件和最近运行。信息本身有效，但没有按现场执行优先级分层，导致活跃任务被大量次要信息包围。

## 批量布局模型

组件维护两套位置：

- `stablePositions`：当前已经提交到画布的稳定坐标。
- `targetPositions`：使用最新可见节点和边计算出的 Dagre 最终坐标。

首次加载空图或一次性打开完整历史结果时，直接采用 Dagre 坐标并适配全图。后续拓扑增量遵循以下规则：

1. 已存在于 `stablePositions` 的节点继续使用原坐标，不因同批新增节点移动。
2. 新节点立即进入画布。优先放在其已知父节点下方，并按稳定 ID 分配临时横向槽位；没有父节点时放入画布右侧的临时槽位。
3. 临时位置必须经过矩形碰撞检测，不得覆盖已有节点或同批其他新节点。
4. 每次新增节点或边都会重置 600ms 稳定窗口。
5. 稳定窗口结束后，将全部节点一次性更新为最新 Dagre 坐标，利用现有 transform transition 完成一次平滑重排。
6. 最终重排动画结束后只执行一次视口适配，避免位置动画与视口动画互相竞争。

节点状态、标签、详情和工具计数变化不属于拓扑变化，不触发布局或视口调整。

## 回放与现场运行

现场 SSE 和历史回放使用同一批量规则。回放单步、拖动进度或直接打开最终结果时，当前可视状态可能一次替换大量节点；组件将其视为一次批次，不逐个播放布局动画。

用户手动点击“适配全图”时立即取消等待中的自动视口适配，但不取消待提交的最终布局。用户点击节点聚焦只改变高亮，不改变布局。

## 关系边路由

不再使用 Vue Flow 默认 `smoothstep` 作为所有边的统一路由。新增纯函数根据关系、稳定节点坐标、节点尺寸、同源边序号和同目标边序号生成 SVG 正交路径。

- `dispatch`、`candidate` 与 `challenge` 是向下主流程边。每个兄弟连接使用独立的水平通道，保持从父节点底部到子节点顶部的方向，不重复覆盖同一整段路径。
- `handoff` 是同层或跨分支协作边。路径从节点侧边离开，经所在层外侧通道到达目标侧边，不穿过同层节点。
- `result` 是反馈边。路径使用图左右两侧的反馈通道返回目标，不从树中心向上回绕；左右侧根据源、目标位置和当前通道占用确定。
- `evidence` 保持低对比度辅助边，使用最短安全路径，避免抢占主流程视觉层级。

同一节点的多条入边和出边按照稳定边 ID 分配端点偏移，箭头不会全部重叠在节点中心。端点偏移限制在节点边界的安全区域内。节点处于临时位置时也使用同一纯函数生成路径，因此批量派发期间边始终跟随当前节点且不依赖最终布局。

聚焦节点时突出其上下游边，其他跨层边降低不透明度。关系类型继续使用现有语义色与虚线节奏，但箭头颜色必须跟随路径颜色。

## 左侧调度栏

左侧栏按现场运行优先级重构：

- 顶部摘要仅显示运行时间、当前并发、完成数和异常数；峰值并发作为当前并发的次级值，不再占独立大块。
- 中部使用“任务 / 动态”标签切换。默认进入“任务”，活跃与等待任务排在前面，已完成任务降低视觉权重但仍可选择。
- “动态”标签仅展示最近调度决策，保持有限高度滚动，不和任务列表同时展开。
- 选中任务详情只在用户选择节点后出现，使用紧凑摘要，不重复展示节点已经表达的类型和状态。
- “变更命中”和“最近运行”进入底部辅助折叠区，默认收起；标题显示数量，展开后在独立滚动区域查看。

标签与折叠状态属于组件本地 UI 状态，不进入 Pinia，不影响路由、任务选择和回放。

## 组件边界

将临时位置分配、碰撞处理和关系边路由放入 `workflowLayout.ts` 的纯函数，避免把几何规则继续堆入 `AgentFlow.vue`。自定义边组件只负责渲染已计算的 SVG 路径；`AgentFlow` 负责保存稳定位置、管理 600ms 定时器和在稳定后提交坐标。

同时清理 `AgentFlow` 模板中重复的放大按钮标签，确保工具栏 DOM 结构合法。

## 验证

- 单元测试覆盖已有节点冻结、新兄弟节点临时展开、无父节点回退、临时位置不重叠和输入顺序稳定。
- 路由测试覆盖四个向下兄弟边通道不完全重叠、同层 handoff 不穿过节点、result 使用外侧反馈通道、多入边端点不重合。
- 组件时序测试覆盖连续事件只提交一次最终布局，状态变化不提交布局，卸载时清理定时器。
- Demo 回放在 Coordinator 批量派发阶段验证：已有输入与 Coordinator 不移动，新子 Agent 立即出现，整批结束后只发生一次平滑重排。
- 左侧栏验证默认只显示任务视图，任务/动态切换正确，辅助区默认收起，选择任务仍能联动任务图。
- 1366×768、1536×864 和 1920×1080 下验证节点无重叠、页面无横向滚动、自动视口不连续缩放。
- `npm run typecheck`、`npm run lint`、`npm run test` 和 `npm run build` 全部通过。

## 不在范围内

不修改 Dagre 的最终分层规则、节点核心视觉、工作台三栏结构、后端事件格式、任务调度策略和回放速度。

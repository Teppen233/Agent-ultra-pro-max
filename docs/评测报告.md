## 评测概述

ReviewCrew Benchmark 基于 Greptile Case Library 构建，从已知开源项目的真实 Bug 修复 PR 中提取案例。每个案例包含漏洞引入前代码（base）和含漏洞代码（head），系统需在 diff 中准确定位并描述已知漏洞。

### 评测指标

- **文件命中**：Finding 指向的文件与已知漏洞文件一致
- **行号命中**：Finding 行号范围与已知漏洞位置重叠（容差 5 行）
- **语义命中**：Finding 描述（类别、影响、触发条件）与已知漏洞一致
- **三层命中率**：所有三层判定均通过才计为"命中"

## 评测命令

### Fake 模式（离线快速验证）

```powershell
# 全量快速评测（每个仓库取一个案例）
python -m benchmark.runner --mode quick --runner fake

# 单个案例评测
python -m benchmark.runner --case sentry-01 --runner fake
```

### 真实模型评测

```powershell
# 配置 .env 中的 LLM_API_KEY 后运行
python -m benchmark.runner --mode quick --runner live
```

### 3. 设置 Base/Head

## 判定逻辑

自动判定使用三层匹配（文件 + 行号 + 语义），结果分为四类：

| 判定 | 说明 | 计数 |
|------|------|------|
| caught | 三层全部命中，自动判定通过 | caught |
| location_only | 文件或行号命中，但语义不匹配 | |
| semantic_only | 语义匹配但位置错误 | |
| missed | 三层均未命中 | |

`needs_human_review = true` 的案例需要人工复核实际审查质量。
